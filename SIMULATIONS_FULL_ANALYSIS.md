# Полный анализ симуляций UWT

Дата анализа: 2026-07-14  
Область: `projects/UWT/modeling` и `projects/UWT/web-app/src/components`  
Статус документа: технический и научно-методологический аудит текущей реализации

## 1. Цель и границы анализа

В UWT существуют два разных класса программ, которые в интерфейсе могут восприниматься одинаково, но имеют различный научный статус:

1. Исследовательское Python-ядро: дискретная реляционная вселенная, построение волновой функции, проверки модели, прогнозирование и именованные эксперименты.
2. Браузерные визуализаторы: интерактивные React/TypeScript-модели, предназначенные прежде всего для объяснения идей UWT.

Их нельзя смешивать. Python-ядро действительно эволюционирует состояние по заданному стохастическому или отжиговому правилу. Большинство браузерных экранов вычисляют детерминированную геометрию непосредственно из положений ползунков и не интегрируют физические уравнения движения.

В документе используются следующие маркеры:

| Маркер | Значение |
|---|---|
| `MODEL` | Воспроизводимое свойство реализованной дискретной модели |
| `DEMO` | Учебная визуализация или процедурная иллюстрация |
| `HYPOTHESIS` | Исследовательская интерпретация, ещё не выведенная и не подтверждённая |
| `BY CONSTRUCTION` | Результат гарантирован выбранным алгоритмом или нормировкой |
| `BUG/RISK` | Реализация или подпись интерфейса допускает неверную интерпретацию |

Анализ основан на полном текущем коде и фактическом запуске всех пяти зарегистрированных экспериментов с конфигурацией по умолчанию. Это не является экспериментальной проверкой природы и не заменяет сравнение с физическими или биологическими измерениями.

## 3. Математическое ядро реляционной вселенной

### 3.1. Пространство состояний

Модель задаёт `n_parts` точек на дискретном торе:

```text
x_i in Z_N^d,
R_ij = (x_j - x_i) mod N,
d_ij = ell0 * ||shortest(R_ij)||_2.
```

Это корректная конечная метризуемая конструкция. Однако метрика на метках частей становится псевдометрикой, если две разные части занимают один узел: тогда `d_ij = 0` при `i != j`. Проверка `identity_of_indiscernibles` справедливо обнаруживает такой случай, но сама динамика коллизии не запрещает.

Размерность `d` и масштаб `ell0` задаются конфигурацией. Поэтому текущая Python-модель не выводит размерность или минимальную длину из одних отношений: она исследует последствия заранее выбранной дискретной геометрии.

### 3.2. Динамика

На каждом шаге каждой координате предлагается случайное смещение из диапазона `[-max_step, max_step]`. Доступны два режима:

| Режим | Правило |
|---|---|
| `random` | Кандидат всегда принимается; это случайное блуждание |
| `annealed` | Используется критерий Метрополиса по гармонической потенциальной энергии |

Ключевой код:

```python
old_r = self.relations()
old_d = self.distances(old_r)
dx = self.rng.integers(-self.cfg.max_step, self.cfg.max_step + 1, size=self.x.shape)
candidate = (self.x + dx) % self.cfg.modulus

if self.cfg.dynamics == "annealed":
    cand_d = self.distances(self.relations(candidate))
    delta_u = self._potential_energy(cand_d) - self._potential_energy(old_d)
    if delta_u <= 0.0 or self.rng.random() < np.exp(-delta_u / self.cfg.temperature):
        self.x = candidate
else:
    self.x = candidate
```

Это валидная вычислительная динамика, но она является дополнительным законом модели. Она не выведена из мереологии или одной только реляционной онтологии UWT.

### 3.3. Наблюдаемые

В текущем ядре определены:

```text
delta_d_ij = |d_ij(k+1) - d_ij(k)|,
v_ij       = delta_d_ij / dt,
variation_i = sum_j rho(delta_R_ij),
stability_i = 1 / (1 + variation_i),
m_i         = m0 + mscale * stability_i,
K_ij        = 1/2 * m_i * v_ij^2,
U_ij        = alpha * d_ij^2,
E_ij        = K_ij + U_ij.
```

Код:

```python
delta_r = (new_r - old_r) % self.cfg.modulus
delta_d = np.abs(new_d - old_d)
velocity = delta_d / self.cfg.dt
offdiag = ~np.eye(self.cfg.n_parts, dtype=bool)
variation = (self.space.rho(delta_r) * offdiag).sum(axis=1)
stability = 1.0 / (1.0 + variation)
mass = self.cfg.m0 + self.cfg.mscale * stability
kinetic = 0.5 * mass[:, None] * velocity**2
potential = self.cfg.potential_alpha * new_d**2
energy_matrix = kinetic + potential
```

Научная интерпретация:

- Скорость является изменением скалярного расстояния, а не векторной скоростью.
- Ускорение и сила также строятся из неотрицательной скорости изменения расстояния. Они не содержат направления взаимодействия.
- Масса задаётся выбранной монотонной функцией устойчивости. Симуляция показывает последствия этой мостовой гипотезы, но не выводит её.
- Потенциал гармонический и выбран заранее.
- Матрица энергии направленная: кинетическая часть пары `(i,j)` использует массу `i`, а сумма по `i != j` считает обе ориентации пары.
- При случайной динамике энергия не обязана сохраняться. При отжиге система взаимодействует с алгоритмическим термостатом, поэтому это также не замкнутая гамильтонова система.

### 3.4. Время и энтропия

История индексируется внешним дискретным шагом, а `dt` задаётся конфигурацией. Следовательно, в Python-ядре время пока не возникает из изменения отношений: изменение отношений измеряется относительно уже заданного шага времени.

Энтропия является энтропией гистограммы попарных расстояний, а не полной термодинамической энтропией. Стрела времени определяется эвристически условием:

```python
net_entropy_production = float(entropies[-1] - entropies[0])
arrow_of_time_detected = net_entropy_production > 0.1
```

Упорядоченный старт способен показать релаксацию. Равновесный старт по умолчанию в основном создаёт флуктуации, поэтому отсутствие стрелы в таком прогоне не опровергает модель, а её наличие требует статистического контроля по многим seed.

## 4. Волновая функция из истории отношений

### 4.1. Реализованная конструкция

Для каждой пары частей вычисляются накопленное действие и устойчивость:

```text
S_ij = sum_k L_ij(k) * dt,
w_ij = 1 / (1 + sum_k |delta d_ij(k)|),
a_ij = sqrt(normalize_j(w_ij)) * exp(i*S_ij/hbar_eff).
```

Затем вклады отношений сворачиваются с гауссовыми ядрами на каждой оси:

```text
psi_i,a(u) = sum_j a_ij * exp(-Delta(u, x_j,a)^2 / (4*sigma_ij^2)).
```

После этого `psi` нормируется, а импульсное представление строится унитарной ДПФ.

Ключевой код:

```python
action_totals, _ = _history_sum(universe.history, "lagrangian_matrix")
action = compensated_elementwise_multiply(action_totals, np.full_like(action_totals, cfg.dt))
delta_totals, _ = _history_sum(universe.history, "delta_distance")
stability = compensated_elementwise_divide(
    np.ones_like(delta_totals),
    compensated_elementwise_add(np.ones_like(delta_totals), delta_totals),
)
weights = np.where(offdiag, stability, 0.0)
row_totals, _ = compensated_axis_sum(weights)
weights = compensated_elementwise_divide(weights, np.broadcast_to(row_totals[:, None], weights.shape))
phase_angles = compensated_elementwise_divide(action, np.full_like(action, cfg.hbar_eff))
amplitude_magnitude = compensated_elementwise("sqrt", weights)
amplitude = (
    compensated_elementwise_multiply(amplitude_magnitude, compensated_elementwise("cos", phase_angles))
    + 1j * compensated_elementwise_multiply(amplitude_magnitude, compensated_elementwise("sin", phase_angles))
)
```

### 4.2. Что действительно установлено

- `MODEL`: из истории реляционной динамики детерминированно строится комплексное поле.
- `BY CONSTRUCTION`: правило Борна выполняется после явной нормировки.
- `BY CONSTRUCTION`: норма сохраняется при переходе к импульсному представлению, потому что используется унитарная ДПФ.
- `MODEL`: когерентная суперпозиция отличается от смеси без фаз.
- `MODEL`: изменение истории отношений меняет амплитуды, фазы и локализацию.

### 4.3. Что пока не установлено

- `psi` не удовлетворяет выведенному уравнению Шрёдингера.
- Между снимками `psi` нет доказанного унитарного оператора эволюции.
- Правило Борна не выведено как единственно возможная вероятность; оно встроено нормировкой `|psi|^2`.
- Интерференция является общим свойством комплексной суперпозиции и сама по себе не различает UWT и стандартную квантовую модель.
- Круговое определение `Delta x` и `Delta p` не гарантирует стандартную границу Гейзенберга без отдельной теоремы для конечного тора.
- Браузерный вариант концептуально похож на Python, но не является численно эквивалентным зеркалом: он строит одну 1D-функцию относительно выбранного центра, использует другой расчёт массы и не применяет Balansis.

### 4.4. Численная политика Balansis

Суммы, осевые суммы, сложение, умножение и матричные произведения проходят через адаптер Balansis. Деление и `exp/cos/sin/sqrt/log` остаются обычными операциями NumPy, что корректно отражено в адаптере.

Риск: в `wavefunction_checks` используются обычные `.max()`, `.min()`, `.mean()`-подобные редукции и `count_nonzero`, хотя отчёт возвращает `raw_float64_reductions: False`. Это поле следует сузить до вычислительного пути построения `psi` или заменить на фактически проверяемую карту операций.

Также `superposition_comp` и `classical_comp` инициализируются значением `1.0`, поэтому возвращаемый максимум компенсации не может быть меньше единицы. Для аудита ошибки более естественным нейтральным значением является `0.0`.

```python
def psi_evolution(cfg: UWTConfig, n_snapshots: int = 6) -> dict:
    universe = RelationalUniverse(cfg)
    chunk = max(1, cfg.steps // n_snapshots)
    series = []
    for k in range(n_snapshots):
        universe.run(chunk)
        series.append({"step": (k + 1) * chunk, **_psi_metrics(universe)})
    return {
        "marker": "MODEL",
        "series": series,
        "spread_drift": series[-1]["mean_position_spread"] - series[0]["mean_position_spread"],
        "note": "снимки psi по растущему префиксу истории; унитарная динамика psi — открытая задача",
    }
```

### 5.2. `condensation`

Код эксперимента:

```python
def condensation(cfg: UWTConfig) -> dict:
    base = replace(cfg, stability_width_gamma=-0.5)
    variants = {
        "annealed": replace(base, dynamics="annealed", temperature=0.2),
        "random": replace(base, dynamics="random"),
    }
    results = {}
    for name, variant_cfg in variants.items():
        universe = RelationalUniverse(variant_cfg)
        universe.run(variant_cfg.steps)
        results[name] = {
            "final_potential_energy": universe._potential_energy(universe.distances()),
            **_psi_metrics(universe),

    return {
        "marker": "MODEL",
        "annealed": results["annealed"],
        "random": results["random"],
        "energy_descent_confirmed": results["annealed"]["final_potential_energy"]
        < results["random"]["final_potential_energy"],
        "localization_delta_spread": results["annealed"]["mean_position_spread"]
```

### 5.3. `quantized_distance`

Код эксперимента:

```python
def quantized_distance(cfg: UWTConfig) -> dict:
    universe = RelationalUniverse(cfg)
    d = universe.distances()
    values = np.unique(np.round(d[~np.eye(cfg.n_parts, dtype=bool)], 12))
    positive = values[values > 0]
    gaps = np.diff(positive)
    return {
        "marker": "MODEL",
        "distinct_distances": int(values.size),
        "min_positive_distance": float(positive.min()),
        "min_spectrum_gap": float(gaps.min()) if gaps.size else None,
        "duration_quantum_dt": cfg.dt,
    }
```

Результат:

```text
distinct_distances     = 249
min_positive_distance  = 4.898979485566
min_spectrum_gap       = 0.012702061750
duration_quantum_dt    = 1.0
```

Критическое уточнение: `4.898979...` — минимальное расстояние в случайной выборке из 24 частей, а не фундаментальный квант решётки. При `ell0=1` глобальное минимальное положительное расстояние разрешённого пространства равно `1`, даже если в конкретном состоянии нет соседних узлов. Аналогично минимальный зазор среди наблюдённых значений не является минимальным зазором полного спектра. Для заявления о кванте необходимо перечислять весь спектр `ell0*sqrt(k)` разрешённых кратчайших векторов или явно называть текущие величины `sample_min_distance` и `sample_min_gap`.

`duration_quantum_dt=1` полностью задан конфигурацией и не выведен из динамики.

| 2 | 42–44 | 6.928203 | 6.474483–6.871345 |
| 3 | 42–44 | 10.392305 | 9.262835–10.261739 |

Все девять прогонов соблюли границу.

Граница следует непосредственно из ограничения координатного шага:

```text
v_max = ell0 * sqrt(dim) * 2 * max_step / dt.
```

Поэтому результат является корректной проверкой реализации `BY CONSTRUCTION`. Он не показывает существование универсальной физической скорости: граница меняется при изменении `max_step`, `ell0`, `dim` или `dt`. Для аналога скорости света нужно обосновать, почему соответствующая комбинация является инвариантом класса допустимых моделей и наблюдателей.

### 5.5. `dimensional_reduction`

Код эксперимента:

```python
def dimensional_reduction(cfg: UWTConfig) -> dict:
    universe = RelationalUniverse(cfg)
    d = universe.distances()[~np.eye(cfg.n_parts, dtype=bool)]
    d = d[d > 0]
    r_grid = np.unique(np.quantile(d, np.linspace(0.05, 0.95, 19)))
    counts = np.array([(d <= r).sum() for r in r_grid], dtype=float)
    log_r, log_n = np.log(r_grid), np.log(counts)
    half = r_grid.size // 2
    dim_small = float(np.polyfit(log_r[:half], log_n[:half], 1)[0]) if half >= 2 else None
    dim_large = float(np.polyfit(log_r[half:], log_n[half:], 1)[0]) if r_grid.size - half >= 2 else None
    return {
        "marker": "HYPOTHESIS",
        "lattice_dim": cfg.dim,
        "effective_dim_small_scale": dim_small,
        "effective_dim_large_scale": dim_large,
        "n_radii": int(r_grid.size),
    }
```

Результат:

```text
lattice_dim                    = 3
effective_dim_small_scale      = 3.001479
effective_dim_large_scale      = 1.706161
n_radii                        = 19
```

Маломасштабная оценка хорошо восстанавливает заданную размерность `3`. Снижение крупномасштабного наклона пока нельзя считать физической размерной редукцией. На конечном торе `N(<r)` неизбежно насыщается полным числом пар, что само по себе уменьшает логарифмический наклон. Дополнительные источники смещения: всего 24 части, зависимые направленные пары, квантильная сетка и один seed.

Нужны контрольные выборки для обычного тора той же размерности, увеличение `n_parts/modulus`, локальная производная, finite-size scaling и сравнение нескольких оценок размерности.

## 6. Прогнозирование и параметрический скан

Модуль прогнозирования сравнивает линейную модель и экспоненциальную релаксацию по внутривыборочной сумме квадратов ошибок. Затем выбранная модель экстраполируется за границы ряда.

Ключевой код:

```python
linear_pred = linear_forecast(y, horizon)
exp_fit = _fit_exp_relaxation(y)
if exp_fit is not None and exp_fit["tau"] is not None and exp_fit["sse"] < linear_sse:
    selected = "exp_relaxation"
else:
    selected = "linear"
```

Ограничения:

- Модель выбирается по in-sample SSE без holdout или rolling validation.
- Случайные ряды энергии и энтропии могут давать убедительный, но ложный тренд.
- Нет доверительных интервалов и оценки ошибки прогноза.
- `forecast_observables` запускает отдельную вселенную с тем же seed; это воспроизводимый повтор модели, а не независимое предсказание.
- Параметрический скан охватывает только три значения `max_step` и три seed в общем эксперименте.

Текущий прогноз следует считать инженерной диагностикой траектории, а не подтверждённым предсказательным аппаратом UWT.

## 7. Анализ браузерных симуляций

### 7.1. Мини-вселенная UWT

Вычислительная идея:

- Части размещаются процедурно на трёхмерной целочисленной решётке.
- Для всех `n(n-1)/2` пар вычисляются расстояние, изменение расстояния, ускорение, масса, импульс, сила и энергия.
- Локальный центр используется как начало относительных координат.
- Видимые устойчивые связи выбираются по порогам расстояния и скорости.
- Размерность оценивается числом координатных осей, на которых есть более одного значения.

Ключевой код:

```typescript
for (let i = 0; i < parts; i += 1) {
  for (let j = i + 1; j < parts; j += 1) {
    const vector = relativeVector(absolute[i], absolute[j])
    const previousVector = relativeVector(previousAbsolute[i], previousAbsolute[j])
    const distance = length3(vector)
    const previousDistance = length3(previousVector)
    const velocity = Math.abs(distance - previousDistance)
    const previousPreviousDistance = length3(
      relativeVector(latticePoint(i, Math.max(0, motion - 2)), latticePoint(j, Math.max(0, motion - 2))),
    )
    const previousVelocity = Math.abs(previousDistance - previousPreviousDistance)
    const acceleration = velocity - previousVelocity
    relationDeltasByPart[i] += velocity
    relationDeltasByPart[j] += velocity
    allRelations.push({ i, j, vector, distance, previousDistance, velocity, acceleration, ... })
  }
}

const masses = relationDeltasByPart.map((delta) => 0.25 + 8 / (1 + delta))
const kinetic = 0.5 * mass * relation.velocity ** 2
const potential = 0.025 * relation.distance ** 2
```

Сильные стороны:

- Явно показано отсутствие отношений при `0–1` части.
- Поворот камеры отделён от относительных координат и не меняет метрики.
- Центр описания можно менять, сохраняя попарные расстояния.
- Компенсированное суммирование используется для аудита агрегатов.
- Сложность `O(n^2)` соответствует полному графу отношений и остаётся приемлемой при `n <= 128`.

Проблемы:

- `BUG`: `centerOffset` не применяется к `absolute` и `previousAbsolute` в текущем состоянии. Ползунки сдвига не меняют текущие отношения, хотя интерфейс утверждает обратное. Смещение используется только в прогнозе следующего состояния.
- Подпись `v = delta d / delta S` не соответствует коду: вычисляется просто `|d_k-d_{k-1}|` без деления на глобальное `delta S`.
- Размерность не возникает из абстрактного графа: она считается по трём заранее заданным координатным осям.
- Масса, потенциал и пороги устойчивости заданы эвристически.
- Процедурная `latticePoint` допускает совпадающие позиции разных частей.
- `motion` является индексом статической формулы, а не результатом интегрирования закона движения.

### 7.2. Браузерная волновая функция

Модель выполняет случайное блуждание частей на кольце `Z_64`, накапливает действие и изменение расстояний относительно выбранного центра, затем строит суперпозицию гауссовых пакетов.

Ключевой код:

```typescript
const weights = new Array<number>(parts).fill(0)
for (let j = 0; j < parts; j += 1) {
  if (j === center) continue
  weights[j] = 1 / (1 + accumDelta[center][j])
  weightSum += weights[j]
}

for (let j = 0; j < parts; j += 1) {
  if (j === center) continue
  const share = weights[j] / weightSum
  const amplitude = Math.sqrt(share)
  const phase = action[center][j] / hbar
  for (let u = 0; u < N; u += 1) {
    const offset = shortest(u - prev[j])
    const kernel = Math.exp(-(offset * offset) / (4 * sigma * sigma))
    psiRe[u] += amplitude * Math.cos(phase) * kernel
    psiIm[u] += amplitude * Math.sin(phase) * kernel
    classical[u] += share * kernel * kernel
  }
}
```

Статус: хорошая иллюстрация предложенной мостовой конструкции `устойчивость -> амплитуда`, `действие -> фаза`. Она не является решением квантовой динамики и не должна подписываться как вывод стандартной квантовой механики.

### 7.3. Атомы вещества

Модель создаёт фиксированную сетку `7x7`, добавляет синусоидальные смещения и соединяет атомы, находящиеся ближе фазового порога.

Ключевой код:

```typescript
const wave = Math.sin(time * params.speed + i * 1.7) * params.jitter * (temperature / 50)
const swirl = Math.cos(time * params.speed * 0.8 + i) * params.jitter * 0.55 * (temperature / 50)

const d = Math.hypot(atoms[i].x - atoms[j].x, atoms[i].y - atoms[j].y)
if (d < params.bond) result.push({ a: i, b: j, d })

const relationEnergy = Math.round(
  atoms.reduce((sum, atom) => sum + atom.energy, 0) / atoms.length,
)
```

Статус: `DEMO`.

Ограничения:

- Нет сил, ускорений, интегратора, столкновений, термостата или сохранения энергии.
- Фазы `solid/liquid/gas` задаются пресетами, а не возникают из параметров модели.
- Газ остаётся деформированной сеткой, а не системой свободных частиц.
- Метрика `relationEnergy` не зависит от связей и координат; подпись `движение + связи` неверна.
- Температура является безразмерным управляющим параметром.

### 7.4. Нейроморфный мозг

Узлы размещаются процедурно, активность определяется синусоидальной функцией, а синапсы создаются по расстоянию, принадлежности модулю или связи с выбранным центром.

Ключевой код:

```typescript
const charge = (Math.sin(i * 1.7 + activity * 0.06) + 1) / 2
const active = charge > params.threshold

const sameCluster = a.cluster === b.cluster
const centered = i === viewCenter || j === viewCenter
if (d < 20 || sameCluster || centered) {
  const weight = Math.max(
    0.05,
    Math.min(1, (sameCluster ? 0.65 : 0.35) + params.plasticity * 0.35 - d / 90),
  )
  const active = (a.active || b.active) && weight > 0.34
  const stable = sameCluster && weight > 0.62 && !active
  result.push({ a: i, b: j, weight, stable, active })
}
```

Статус: `DEMO`.

Ограничения:

- Нет временной мембранной динамики, спайков, рефрактерности, STDP или обучения.
- «Память» определяется как неактивная внутрикластерная связь выше порога.
- Выбор наблюдателя `viewCenter` добавляет связи в сам граф и меняет когерентность и энергию. Центр описания должен менять представление, но не физическое состояние сети.
- Пластичность является коэффициентом формулы веса, а не результатом истории обучения.
- Режимы являются ручными пресетами.

### 7.5. Электроны

Положения задаются аналитическими орбитоподобными кривыми. После размещения вычисляется кулоноподобный индекс `repulsion/r^2`, но он не влияет на последующее положение электронов.

Ключевой код:

```typescript
const shell = 10 + ((i * 13) % 34) * params.confinement + (regime === 'plasma' ? i % 9 : 0)
const angle = i * 2.399 + time * 0.07 + fieldStrength * 0.004
const fieldDrift = (fieldStrength - 50) * params.field * 0.24

const distance = Math.hypot(a.x - b.x, a.y - b.y)
const force = params.repulsion / Math.max(1.2, distance ** 2)
const paired = a.spin !== b.spin && distance < 16 && regime !== 'plasma'
```

Статус: `DEMO`.

Критические ограничения:

- Сила не интегрируется и не определяет траекторию.
- Нет притяжения к ядру, электромагнитного поля, волновой функции, принципа Паули или единиц измерения.
- Сумма `1/r^2` подписана как энергия отталкивания, хотя кулоновская потенциальная энергия масштабируется как `1/r`; реализованная величина ближе к индексу силы.
- Спин-пары определяются только противоположностью меток и близостью.
- Переключение режимов вручную меняет коэффициенты и не является фазовым переходом.

### 7.6. ДНК

Модель строит двойную спираль, комплементарные пары, распределённый центр и перспективную 3D-проекцию.

Ключевой код:

```typescript
const base = baseAt(i, twist / 10)
const complement = pair[base]
const angle = i * 0.58 + twist * 0.025
const p1 = { x: Math.cos(angle) * radius, y, z: Math.sin(angle) * radius }
const p2 = { x: Math.cos(angle + Math.PI) * radius, y, z: Math.sin(angle + Math.PI) * radius }

const mutated = damage === 'mutation' && i === activeFocus
return {
  id: i,
  base: mutated ? complement : base,
  complement: mutated ? base : complement,
  p1,
  p2,
  damaged,
  mutated,
}
```

Статус: `DEMO`.

Проблемы:

- `BUG`: параметр геометрического скручивания входит в seed функции `baseAt`; изменение формы спирали изменяет генетическую последовательность.
- «Мутация» меняет основания местами, но сохраняет корректную комплементарность пары. Это замена пары, а не моделирование несовпадения или ошибки репликации.
- «Разрыв» меняет счётчик связей, но визуальный элемент связи всё равно создаётся с CSS-классом `damaged`.
- Устойчивость не ограничена сверху и при длинной нормальной последовательности может превышать `100%`.
- Информационная мера `2*length - penalties` эвристична и не является энтропией Шеннона или биологической функциональной информацией.
- GC-пары учитываются одинаково для `G-C` и `C-G`, что корректно, но реальное различие двух и трёх водородных связей в энергии не моделируется.

### 7.7. MagicBrain

Компонент содержит две независимые системы:

1. Процедурную TypeScript-визуализацию графа, построенную из base-4 genome.
2. Генерируемый Python-код, создающий настоящий `magicbrain.TextBrain` и запускающий доступный train loop.

Ключевой код процедурного графа:

```typescript
const g = genomeValue(safeGenome, i)
const ring = 11 + ((i * 17 + g * 13) % 35)
const charge = (Math.sin(i * 1.31 + activity * 0.06 + g) + 1) / 2
const module = (g + layer) % 6

const geneAffinity = genomeValue(safeGenome, i + j) / 3
const weight = Math.max(
  0.05,
  Math.min(1, (sameModule ? 0.5 : 0.2) + geneAffinity * 0.28 + plasticity / 220 - d / 120),
)
links.push({
  a: i,
  b: j,
  weight,
  stable: weight > 0.55 && sameModule,
  active: (a.active || b.active) && weight > 0.32,
})
```

Генерируемый исполнимый код:

```python
from magicbrain import TextBrain
from magicbrain.tasks.text_task import train_loop

genome = "..."
text = "uwt memory uwt memory uwt stable memory "
chars = sorted(set(text + "uwt"))
stoi = {char: index for index, char in enumerate(chars)}
brain = TextBrain(genome, vocab_size=max(vocab_size, len(chars)))
train_loop(brain, text=text, stoi=stoi, steps=steps)
```

Статус: процедурный граф — `DEMO`; Python-блок — реальный интеграционный сценарий MagicBrain.

Ограничения:

- Визуальный граф не читается из созданного `TextBrain`; его узлы, веса и активности не являются состоянием реально обученной модели.
- Число шагов обучения влияет только на Python-блок и не меняет граф на экране.
- «Память» в графе определяется порогом процедурного веса, а не результатом обучения.
- `Sparsity` вычисляется как доля активных нейронов. В обычной терминологии это плотность активности; sparsity обычно равна доле неактивных элементов.
- `Energy = sum(weights)` не связана с энергетической функцией MagicBrain.
- Для научного демо визуализация должна получать сериализованные реальные веса, спайки и метрики после выполнения Python-кода.

## 8. Сквозные выводы

### 8.1. Что уже является сильной стороной проекта

- Есть воспроизводимое Python-ядро с фиксируемым seed и явной конфигурацией.
- Формально разделены `MODEL` и `HYPOTHESIS` в реестре экспериментов.
- Метрическая проекция и кинематическая граница имеют прозрачные формулы.
- Учитывается численная устойчивость через Balansis и компенсационные остатки.
- Волновая конструкция явно показывает, где вводятся амплитуда, фаза, ядро и нормировка.
- `psi_evolution` честно признаёт отсутствие унитарной динамики.
- Браузерные визуализаторы хорошо объясняют реляционный язык «части — отношения — устойчивые структуры».

### 8.2. Главная научная граница

Текущие симуляции отвечают на вопрос:

> Что происходит внутри конкретно выбранной дискретной реляционной модели?

Они пока не отвечают на более сильный вопрос:

> Почему именно эти законы динамики, массы, действия, вероятности и энергии необходимо следуют из аксиом Теории Единого Целого?

Почти все физически содержательные величины появляются через мостовые определения:

```text
отношения -> выбранная метрика,
устойчивость -> выбранная формула массы,
расстояние -> гармонический потенциал,
действие -> фаза,
устойчивость -> амплитуда,
ограниченный шаг -> максимальная скорость.
```

Симуляции полезны для исследования совместимости этих мостов. Они не доказывают их единственность или физическую истинность.

### 8.3. Результаты, истинные по построению

Следующие результаты нельзя подавать как независимые предсказания:

| Результат | Почему гарантирован |
|---|---|
| Нормировка `sum |psi|^2 = 1` | `psi` явно делится на норму |
| Parseval/норма импульсного представления | Используется унитарная ДПФ |
| Интерференция | Комплексные амплитуды складываются до возведения в квадрат |
| Ограничение скорости | Координатный шаг ограничен `max_step` |
| Дискретность расстояний | Состояния заранее живут на конечной решётке |
| Снижение энергии при отжиге | Критерий принятия использует ту же энергию |

Это не делает эксперименты бесполезными. Они проверяют корректность реализации и внутреннюю согласованность, но для физической проверки нужны результаты, не встроенные непосредственно в алгоритм.

| P1 | Веб-`psi` называется зеркалом Python, но алгоритмы различаются | Возможна ложная уверенность в численном соответствии |
| P1 | `psi_evolution` теряет остаток шагов | Финальный снимок не соответствует `cfg.steps` |
| P1 | Forecast выбирается по in-sample SSE | Нет оценки реальной предсказательной способности |
| P1 | Аудит `raw_float64_reductions=False` шире фактической гарантии | Численная декларация сформулирована слишком сильно |
| P2 | UI-состояния симуляций сбрасываются при переключении вкладок | Нельзя сравнивать сценарии без ручной фиксации параметров |
| P2 | Нет единого экспорта конфигурации, результатов и версии модели | Затруднены воспроизводимость и публикация результатов |

## 10. Рекомендуемая программа доработки

### Этап 1. Исправить достоверность интерфейса

1. Применить `centerOffset` к текущим, предыдущим и предпредыдущим координатам мини-вселенной.
2. Переименовать электронную метрику в `force index` или реализовать отдельно силу `1/r^2` и потенциальную энергию `1/r`.
3. Отделить seed последовательности ДНК от параметра скручивания, ограничить устойчивость диапазоном `[0,100]` и определить мутацию как реальное изменение пары.
4. Убрать `viewCenter` из условия создания синапсов; центр должен влиять только на подсветку.
5. Явно маркировать интерфейсы как `DEMO`, `MODEL` или `HYPOTHESIS`.

### Этап 2. Создать один источник вычислительной истины

1. Вынести математические вычисления из React-компонентов в версионированные model-модули.
2. Синхронизировать браузерную `psi` с Python через общий формат состояния или WebAssembly/Pyodide-вызов канонического ядра.
3. Получать граф MagicBrain из реально исполненной модели, а не из отдельной процедурной формулы.
4. Добавить cross-language parity checks для одинаковых seed и параметров.

### Этап 3. Усилить эксперименты

1. Для каждого результата запускать ансамбль seed и публиковать среднее, стандартное отклонение и доверительный интервал.
2. Добавить нулевые модели: обычное случайное блуждание, случайные фазы, фиксированные массы, непрерывная решётка и случайный граф.
3. Разделить calibration и validation; прогнозы оценивать rolling backtest-ом.
4. Для размерности проводить finite-size scaling по `n_parts`, `modulus` и `dim`.
5. Для квантования перечислять полный допустимый спектр пространства, а выборочные минимумы маркировать отдельно.
6. Для `psi` искать оператор перехода между снимками и измерять отклонение от унитарности.

### Этап 4. Перейти к различающим предсказаниям

Перспективным результатом будет не ещё одна визуально правдоподобная траектория, а наблюдаемая величина, которая:

1. выводится из минимальных аксиом и заранее зафиксированных мостовых законов;
2. не является следствием нормировки или ограничения алгоритма;
3. отличается от стандартной теории или её параметризации;
4. сохраняется при смене координат и центра описания;
5. имеет количественную погрешность и условие опровержения.

## 11. Итоговая оценка

Текущий симуляционный контур UWT уже является хорошей исследовательской лабораторией и сильным средством объяснения реляционной идеи. Наиболее зрелая часть — конечная дискретная модель с воспроизводимой историей, метрическим аудитом, параметрическим сканом и явным реестром экспериментов.

Главное ограничение состоит не в недостатке визуализаций, а в разрыве между тремя уровнями:

```text
онтологические аксиомы UWT
        -> мостовые физические определения
        -> вычислительные алгоритмы и наблюдаемые.
```

Сейчас второй уровень в основном задаётся вручную. Поэтому корректный вывод из симуляций таков:

> Реализованные мостовые гипотезы образуют вычислимо согласованную и исследуемую модель, но результаты пока подтверждают свойства этой модели, а не фундаментальные законы природы.

Следующий научный шаг — сократить число свободно выбранных мостов, доказать инвариантность оставшихся и получить хотя бы одно различающее количественное предсказание.
