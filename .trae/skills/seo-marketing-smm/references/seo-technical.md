## Порядок аудита

Строго снизу вверх — нет смысла улучшать сниппет страницы, которую робот не может получить.

1. **Доступность**: DNS, TLS, коды ответа, редиректы (цепочки, http→https в один хоп), `/404`.
2. **Индексируемость**: `robots.txt`, `X-Robots-Tag`, `<meta name="robots">`, canonical, sitemap.
3. **Дубли**: `/page` vs `/page/` vs `/page.html`, RSC-пейлоады `.txt`, апекс vs www, параметры.
4. **Разметка сниппета**: title, description, H1, OG/Twitter, JSON-LD.
5. **Контент для не-JS-краулера**: что реально лежит в статическом HTML (см. deck-ловушку ниже).
6. **Скорость и CWV** — последним, это оптимизация, а не блокер индексации.

Запускать `scripts/seo_check.py --site <url>` — он покрывает шаги 1–4 автоматически.

## Что проверять и чем

```bash
# коды и заголовки без тела
curl -sI https://site/page

# цепочка редиректов целиком
curl -sIL https://site/page | grep -E '^HTTP|^location'

# что видит краулер без JS (важнее, чем то, что видно в браузере)
curl -s https://site/page | grep -o '<title>[^<]*</title>'
curl -s https://site/page | python3 -c "import sys,re;h=sys.stdin.read();print(len(re.sub('<[^>]+>',' ',h)))"

# JSON-LD одним куском
curl -s https://site/page | python3 -c "import sys,re;[print(m) for m in re.findall(r'application/ld\+json\">(.*?)</script>',sys.stdin.read(),re.S)]"
```

Внешние валидаторы: validator.schema.org (разметка), search.google.com/test/rich-results,
PageSpeed Insights (квота выбивается быстро — не полагаться на него как на единственный источник).

## Приоритет находок

| Уровень | Признак | Примеры |
|---|---|---|
| FAIL | страница не может попасть в индекс или попадает не та | 404 на robots/sitemap, noindex на боевой странице, canonical на чужой URL, дубль с полным текстом |
| WARN | попадает, но проигрывает | нет description, дубли title, лишний хоп редиректа, отсутствие структурированных данных, тяжёлый OG |
| OK | соответствует | — |

В отчёте для каждой находки давать команду воспроизведения. «Кажется, медленно» — не находка.

## Next.js static export: что умеет и где ломается

`output: 'export'` — это пререндер, поэтому:

- **Работают** metadata routes: `app/robots.ts` и `app/sitemap.ts` собираются в статические файлы.
  Не писать `public/robots.txt` руками, если есть `app/robots.ts` — будет конфликт.
- **Работает** `generateStaticParams` — динамические маршруты вида `/services/[slug]` пререндерятся
  на билде. Это штатный способ развернуть hub-and-spoke без бэкенда.
- **Не работают** middleware, редиректы и заголовки из `next.config` — всё это делает nginx.
- **Ловушка RSC-пейлоадов**: рядом со страницей рождаются `.txt`-файлы с полным текстом. Их нужно
  закрывать `X-Robots-Tag: noindex` и/или 301, иначе это дубль всего контента.
- **Ловушка `lang`**: атрибут, выставленный из `useEffect`, для краулера не существует. Язык должен
  быть в статическом HTML — раздельные root layouts через route groups.
- **Ловушка «красивого» интерфейса**: любой контент, скрытый до гидратации (`visibility: hidden`,
  deck/slider-режимы, аккордеоны на JS), для не-JS-краулера отсутствует. Посадочные страницы делать
  обычным вертикальным потоком: SEO-страница и wow-сцена — разные шаблоны.

## nginx за Traefik: три ловушки, на которых уже наступали

Специфика xteam.pro и uwt.xteam.pro, повторяется в каждом статическом сайте на этом хосте:

1. **`add_header` в `location` молча отменяет унаследованные от `server`.** Из-за этого
   security-заголовки не отдавались на страницах. Решение: вынести в `deploy/headers.conf` и делать
   `include` в каждом `location`, где есть свой `add_header`.
2. **Убрать `$uri/` из `try_files` в `location /` → главная отдаёт 404** (`/` — директория, не
   матчит ни `$uri`, ни `$uri.html`). Нужен отдельный `location = / { try_files /index.html =404; }`.
3. **Редирект дублей нельзя вешать на `location = /index.html`** — `/` внутренне переписывается в
   `/index.html`, получается вечный цикл. Матчить только по `$request_uri` (переживает internal
   rewrite), а Location писать абсолютным `https://` — иначе nginx за Traefik отдаёт `http://`.

После `docker compose up -d --build` Traefik несколько секунд отдаёт старый контейнер — не спешить
с выводом «не задеплоилось», перепроверить через паузу.

## Structured data

Минимум для B2B-сайта услуг:

- `Organization` (+ `sameAs` на реальные профили, `address`/`telephone` после появления реквизитов)
- `WebSite` (+ `inLanguage`)
- `WebPage` / `CollectionPage` на каждой странице, связанные через `@id` с Organization и WebSite
- `Service` на каждой странице услуги (`provider` → `@id` организации, `areaServed`)
- `BreadcrumbList` на вложенных страницах
- `FAQPage` — только если блок вопросов реально есть на странице
- `Article` / `TechArticle` в блоге, с `author` и `datePublished`

Связывать сущности через `@id`, а не дублировать объекты. Проверять валидатором до деплоя.

## Мультиязычность

- `hreflang` взаимный и с `x-default`; в static export удобнее задавать в `sitemap.ts`.
- Языковые версии на разных URL (`/` и `/en`), а не переключением на клиенте.
- `lang` в статическом HTML (см. ловушку выше), `og:locale` под каждую версию.

## Core Web Vitals

Для сайтов с WebGL-сценой headless-замер со SwiftShader непоказателен — числа хуже реальных в разы.
Достоверные источники: поле CrUX (GSC → Core Web Vitals) и Метрика (Вебвизор → скорость загрузки).
Приоритет оптимизации: LCP (обычно герой-изображение или шрифт) → INP (тяжёлые обработчики скролла)
→ CLS (шрифты и картинки без размеров). OG-изображение держать до ~300 КБ, иначе мессенджеры не
покажут превью.

## Проверка аналитики

`next/script` со `strategy="afterInteractive"` **не кладёт** `<script>` в статический HTML — тег
вставляет рантайм при гидратации. Поэтому `curl | grep googletagmanager` ничего не доказывает.
Проверять headless-браузером с перехватом сетевых запросов:

- GA4 → запрос к `/g/collect` с нужным `tid`
- Метрика → запрос к `mc.yandex.ru/watch/<id>`

Рабочий паттерн на хосте: `puppeteer-core` + `/root/.cache/puppeteer/chrome-headless-shell/.../chrome-headless-shell`.
Для WebGL-страниц добавлять `--use-angle=swiftshader` (обычный `--disable-gpu` не даёт WebGL).
Если счётчик вставлен через `<noscript><img src="mc.yandex.ru/watch/ID">`, его видно и в `curl` —
это самый дешёвый признак присутствия Метрики.
