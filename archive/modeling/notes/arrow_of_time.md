# Заметка: стрела времени в реляционной модели UWT

**Статус:** воспроизводимое вычислительное наблюдение
**Область:** пакет `uwt_modeling` (симулятор `RelationalUniverse`)
**Дата:** 2026-07-09

---

## 1. Проблема

Проверка теории `RelationalUniverse.theory_checks()` содержит блок `time`, оценивающий
термодинамическую стрелу времени через **пошаговую монотонность энтропии** —
метрику `entropy_non_decrease_ratio` (доля шагов с `ΔS ≥ 0`).

На практике эта метрика держится около **0.5 при любом размере системы** и любом
числе шагов, то есть формально «стрела времени» в модели почти не подтверждается.
Естественный вопрос: это дефект теории или дефект диагностики?

## 2. Диагноз

Причина — в **начальном условии**, а не в динамике. Конструктор инициализировал
состояния частей `x` равномерно случайно на торе `Z_N^d`:

```python
self.x = self.rng.integers(0, cfg.modulus, size=(cfg.n_parts, cfg.dim))
```

Равномерное распределение на торе — это уже **максимально-энтропийное (равновесное)**
состояние. Релаксировать не из чего: энтропия лишь флуктуирует вокруг равновесного
значения, и доля неубывающих шагов оказывается ≈ 0.5 по построению. Увеличение
системы это не лечит (см. таблицу ниже) — оно лишь уменьшает амплитуду флуктуаций
вокруг того же равновесия.

Второй, независимый эффект: энтропия оценивается из **гистограммы** попарных
расстояний и потому шумная. Пошаговая монотонность такой оценки остаётся ≈ 0.5
**даже при явной макроскопической релаксации** — то есть `entropy_non_decrease_ratio`
структурно неспособна детектировать стрелу времени.

### Стрела времени не зависит от размера при равновесном старте

Равновесный старт, усреднение по 5 seed, `modulus=48`, `steps=150`:

| n_parts | доля неубыв. | mean ΔS  | S_init | S_final |
|--------:|-------------:|---------:|-------:|--------:|
|       8 |        0.511 | +0.00052 |  1.684 |   1.762 |
|      16 |        0.497 | +0.00047 |  2.436 |   2.506 |
|      32 |        0.497 | −0.00017 |  3.133 |   3.107 |
|      64 |        0.501 | −0.00021 |  3.133 |   3.102 |
|     128 |        0.498 | +0.00001 |  3.100 |   3.101 |

Никакого систематического роста энтропии — чистое производство ≈ 0 на всех масштабах.

## 3. Правильный тест: релаксация из упорядоченного состояния

Стрела времени в статистической механике — это релаксация из **низкоэнтропийного
(упорядоченного)** начального состояния к равновесию. Чтобы её наблюдать, нужно
стартовать из порядка, а мерить — **чистое производство энтропии**
`net_entropy_production = S_final − S_init`, а не пошаговую монотонность.

Усреднение по 12 seed, `n_parts=64`, `dim=3`, `modulus=48`, `steps=250`:

| Старт               | net производство (mean [min, max]) | сглаж. монотонность |
|---------------------|-----------------------------------:|--------------------:|
| `ordered` extent=1  |            **1.044** [0.931, 1.121] |               0.559 |
| `ordered` extent=2  |            **0.712** [0.645, 0.816] |               0.566 |
| `equilibrium`       |          **−0.002** [−0.095, 0.045] |               0.506 |

Выводы:

1. **Чистое производство энтропии чисто разделяет режимы.** Из упорядоченного старта
   оно устойчиво положительно (≥ 0.65 нат), из равновесного — статистический ноль
   (|net| ≤ 0.095). Стрела времени в модели **есть**, но видна только из порядка.
2. **Пошаговая монотонность (даже сглаженная) не разделяет режимы** (≈ 0.51–0.57
   в обоих случаях) — она измеряет шум гистограммного оценщика, а не термодинамику.
   Это подтверждает, что исходная метрика была неправильной линзой.

## 4. Что добавлено в модель

### Конфигурация (`config.py`)

- `init: str = "equilibrium"` — режим начального состояния (`"equilibrium"` | `"ordered"`).
- `ordered_extent: int = 3` — размер угла решётки для упорядоченного старта
  (все части сжаты в куб `[0, extent)^d`; меньше extent ⇒ ниже стартовая энтропия).
- `entropy_smoothing_window: int = 15` — окно сглаживания энтропии для диагностики.

### Симулятор (`universe.py`)

- `RelationalUniverse._initial_positions()` — раскладывает старт по режиму `init`.
- Блок `theory_checks()["time"]` расширен полями:
  - `net_entropy_production` — **главный** макроскопический критерий стрелы времени;
  - `arrow_of_time_detected` — `net_entropy_production > 0.1` нат
    (порог ≈ 2× потолка равновесных флуктуаций, много ниже ordered-производства);
  - `smoothing_window`, `smoothed_non_decrease_ratio` — сглаженная монотонность
    (сохранена как диагностика; демонстрирует, что монотонность всё равно ≈ 0.5).

Прежние поля (`entropy_non_decrease_ratio`, `mean_entropy_delta`) оставлены для
совместимости.

### CLI

```bash
uwt-model --init ordered --ordered-extent 2 --parts 48 --steps 120 --modulus 40 --out results/run.json
```

## 5. Воспроизведение

```python
from uwt_modeling import UWTConfig, RelationalUniverse

for init in ("ordered", "equilibrium"):
    u = RelationalUniverse(UWTConfig(n_parts=64, dim=3, modulus=48, steps=200,
                                     init=init, ordered_extent=2, seed=3))
    u.run()
    t = u.theory_checks()["time"]
    print(init, t["net_entropy_production"], t["arrow_of_time_detected"])
# ordered      0.57  True
# equilibrium  0.03  False
```

Тест: `tests/test_theory_checks.py::test_arrow_of_time_requires_low_entropy_start`.

## 6. Замечание для интерпретации теории

Модель **не нарушает** второе начало термодинамики — она просто по умолчанию
стартовала в равновесии, где второму началу нечего производить. Содержательное
утверждение UWT о стреле времени корректно формулируется так:

> при упорядоченном (низкоэнтропийном) начальном условии реляционная динамика
> даёт устойчивое положительное производство энтропии и релаксацию к равновесию;
> направление времени — следствие начального условия, а не отдельного постулата.

Это ровно то, что должна проверять диагностика, и теперь она это проверяет.
